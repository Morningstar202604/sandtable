## なぜ将台なのか

多くの兵棋プロジェクトは戦場をシミュレートします。将台はその背後の**指揮機械**を
シミュレートします：高級司令部の意図が層ごとに命令へ分解され、部下が自主的に実行して
報告し、情報が遅延と喪失の中で劣化する様子。地図は背景にすぎず、**組織こそが
シミュレート対象**です。

```
意図(上部) → 計画(参謀) → 命令(軍→師→連隊) → 行動(世界エンジン) → 報告/警報(上へ)
     ▲                                                          │
     └────────────── 遅延 · 喪失 · 歪み（組織摩擦）──────────────┘
```

各陣営は**閉じたループ**です：自分の報告で知ったことだけを知り、敵は自軍の偵察でしか
見えず、通信が劣化すると命令は遅れたり失われたりします。部隊を直接操作するのではなく、
自律的に動く組織を観察（そして*演出部*として攪拌）します。

## 主な特徴

**指揮機械**

- **多陣営設計**——陣営数は自由で「交戦関係」（`WAR_PAIRS`）を明示：同盟同士は隣接
  しても発砲しません。ノルマンディーは 米軍/英加軍/ドイツ軍 の 3 陣営で、各陣営が
  独立した指揮系統・情報・スコアを持ちます。
- **分離は強制**——陣営ごとに独立したメッセージバス・情報ストア・記憶。陣営をまたぐ
  メッセージはバス層で拒否。陣営内でも共有ゼロ：軍団長が知っているのは届いた報告だけ。
- **個性を持つエージェント**——各ポジションにシナリオ定義の指揮スタイルと歴史的性格
  （「モンゴメリー式の慎重さ」「狂信的な第12SS」「装甲予備を温存する遅鈍な独軍上部」）
  をロールカードへ注入。ポジション単位の動作パラメータ上書きも可能。
- **組織摩擦のノブ**——メッセージ遅延・喪失率・電子戦妨害をリアルタイム調整可能。
  指揮官が遅れた不完全な情報で判断し、重要命令が妨害で途絶える様を観察できます。
- **最前線の戦術エージェント**——各戦闘単位が軽量な戦術エージェントを持ち、局所認識・
  自律行動（接触で交戦/損傷で後退/就地防御）・非同期報告を行います。指揮系統の最下層は
  AI 駆動であり、死んだデータではありません。

**決定論的エンジン**

- **決定論的エンジン、LLM は意思決定のみ**——移動/戦闘/補給/偵察/天候/航空阻害/
  補給所争奪/目標スコアは固定シードのエンジンが解決（同一シード ⇒ 同一戦役）。LLM
  （またはルールフォールバック）は型付きメッセージと命令のみ出力し、幻覚的な命令は
  スキーマ検証で拒否されます。
- **九つの戦場要素**——昼夜、疲労と休養、士気と崩壊、電子戦、砲兵制圧、補給線
  （弾薬/燃料/糧食）、戦争の霧と偽装、指揮範囲、兵種協同、工事と要塞、天候効果、
  部隊経験、指揮官特性、行軍/戦闘隊形——すべて戦闘式で相互作用します。

**指揮コンソール（Web UI）**

- **COP 指揮センター**——NATO 式部隊記号、プロシージャル地形テクスチャ、戦闘エフェクト
  （爆発/砲撃弾道/火力線）、部隊選択・詳細パネル、ホバーツールチップ、兵力比バー、
  昼夜進行表示。
- **作戦ブリーフィング**——各シナリオが開始前に表示される作戦ブリーフィングを同梱。
  推演中は 5 ティックごとに指揮サマリー（天候/目標支配/兵力比）を出力。
- **演出部（導調）**——推演中に任意の状況（新任務、敵軍集結、天候急変、情報通報）を
  任意のポジションへ注入。指定ティックで自動発火する*導調スクリプト*も作成可能。

**LLM とアフターアクション**

- **AI シナリオインポート**——戦史資料・編制メモ・ニュースを貼り付けると LLM が
  陣営/部隊/目標/意図を分類・抽出し、すぐ遊べるシナリオを生成。
- **アフターアクション指標とリプレイ**——陣営別の指揮系統健全性、戦力/スコア/目標支配
  カーブ、Markdown のアフターアクションレポート、そして `runs/*/events.jsonl` の
  全イベントログをオフラインリプレイ可能。
- **スターリングラード・シナリオ**——ヴォルガ川と駅を巡る都市消耗戦：吹雪→曇り→晴れの
  天候スクリプト、市街戦、双方の増援。

## クイックスタート

**Python 3.10+** が必要です。LLM キーなしでも動作します——内蔵ルールポリシーは完全
オフライン・決定論的です。

```bash
# 1. インストール
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e .

# 2. Web コンソールを起動
python -m wargame.cli serve      # → http://127.0.0.1:8300
```

コンソールを開き、ロビーでシナリオを選んでブリーフィングを読み、演習を開始します。
LLM 判断を有効にするには**設定**パネルか `.env` にキーを設定——[LLM モード](#llm-モード) 参照。

## シナリオ

| シナリオ | id | 説明 |
|---|---|---|
| 渡河強襲 | `cross_river` | 架空の訓練シナリオ：2 本の橋が隘路となり組織摩擦が前面に出る |
| ノルマンディー 1944 | `normandy` | 3 陣営の歴史シナリオ：5 海岸上陸 vs 大西洋の壁と装甲予備隊 |
| スターリングラード 1942 | `stalingrad` | 2 陣営の都市消耗戦：ヴォルガ川と駅、吹雪→曇り→晴れ、双方の増援 |

シナリオは `src/wargame/scenarios/` 配下のプレーンなデータモジュールで、統一インターフェース
（`SCENARIO_NAME`、`build_world()`、`FACTIONS`、`WAR_PAIRS`、`DEFAULT_INTENTS`、
`PLANS`、`RECON_TARGET`、任意の `CAMP_NAMES`、`ORG_TITLES`、`ORG_CONFIG`、`WEATHER`、
`AIR_POWER`、`OBJECTIVES`、`REINFORCEMENTS`、`BRIEFING`）をエクスポートし、
`scenarios/__init__.py` に 1 行登録するだけでロビーに表示されます。[開発](#開発) 参照。

## Web コンソールの使い方

単一ページのダークな指揮センター UI で、2 つのモードがあります。

**ロビー/設定**（左ナビ：想定庫 / 兵力編成 / 演出部設定 / エージェントデバッグ）:

- **想定庫**——シナリオ閲覧、ブリーフィング閲覧、AI インポート、戦役パラメータ調整。
- **兵力編成**——各ポジションのロールカード・権限・動作パラメータ上書きを確認。
- **演出部設定**——各陣営の開局意図、組織摩擦、導調スクリプトを設定。
- **エージェントデバッグ**——各エージェントの受信箱/タスク/記憶/決定履歴をライブ確認。
  LLM の生のリクエスト/レスポンスをリプレイし、JSON または Markdown のアフターアクション
  レポートをエクスポート。

**デッキ（演習ビュー）**:

- **地図**——パン/ズーム可能なキャンバス：NATO 記号、プロシージャル地形、戦闘エフェクト、
  昼夜暗化、兵力比バー。
- **電文フィード（戦況電文）**——指揮系統上の全メッセージ（意図→計画→命令→確認→報告→
  請求→警報→情報）を種別ごとに色分けしフィルタ可能。
- **最前線部隊（一線分隊）**——各戦術エージェントの状態と直近の行動。
- **レビューパネル（演出部講評）**——指揮系統健全性のライブ統計と戦力/スコア/目標支配
  カーブ。Markdown アフターアクションレポートをワンクリックでエクスポート。

## 指揮統制モデル

- **任務指揮（Auftragstaktik）**——命令は意図を運び、手順ではない。下位が「どうやるか」を
  選び、系統をたどって報告します。
- **メッセージ種別**——`intent`（上部意図）、`plan`（参謀提案）、`order`（命令下達）、
  `ack`（確認上申）、`sitrep`（状況報告）、`request`/`escalation`（請求/警報）、
  `intel`（情報通報）。
- **摩擦**——全メッセージが設定可能な遅延・喪失率・電子戦妨害を伴ってバスを流れます。
  高優先メッセージは部分的に保護され、軍事的な冗長チャネルを模します。
- **分離**——陣営ごとにバス・情報ストア・記憶を 1 つずつ。共有されるのは世界エンジン
  （と敵の火力）だけです。
- **演出部**——任意のタイミングで任意のポジションに状況を注入。スクリプトで指定ティックに
  自動発火も可能。演習は攪拌できる進行中の実験です。

## LLM モード

`LLM_API_KEY` を設定すると、エージェントは任意の OpenAI 互換エンドポイントで**ネイティブ
ツールコール**（構造化出力）により判断します。失敗時は JSON プロンプト経路、さらに決定論的
**ルールポリシー**へ自動フォールバック。すべて環境変数で切替可能:

| 変数 | デフォルト | 意味 |
|---|---|---|
| `LLM_API_KEY` | （空） | API キー。空 ⇒ ルールポリシー（オフライン）。コミット厳禁。 |
| `LLM_BASE_URL` | `https://api.openai.com/v1` | OpenAI 互換エンドポイント全般（OpenAI / DeepSeek / Qwen / Ollama …） |
| `LLM_MODEL` | `gpt-4o-mini` | モデル名 |
| `WARGAME_LLM_TOOLS` | `1` | ネイティブツールコール構造化出力；`0` = JSON プロンプト経路 |
| `WARGAME_LLM_RETRY` | `2` | リクエストあたりのリトライ回数（指数バックオフ） |
| `WARGAME_LLM_TIMEOUT` | `90` | リクエストあたりのタイムアウト（秒） |
| `WARGAME_MAX_LLM_CALLS` | `40` | ティックあたりの LLM 呼び出し予算上限 |
| `WARGAME_LLM_FALLBACK` | `1` | 失敗時ルールポリシーへ自動フォールバック；`0` = エラーを直接表示 |
| `WARGAME_LLM_TOP_P` | `1` | 核サンプリング |
| `WARGAME_LLM_FREQ_PENALTY` / `WARGAME_LLM_PRESENCE_PENALTY` | `0` | サンプリングペナルティ |
| `WARGAME_SEED` | `7` | 世界 RNG シード（同一シード ⇒ 同一戦役） |

作業ディレクトリ隣の `.env`、Web の**設定**パネル、または環境変数で設定できます。各 LLM
決定はトレースに記録され（プロンプト/レスポンス/遅延/試行回数）、エージェントデバッグで
リプレイ可能です。

## CLI（ヘッドレス）

```bash
# ヘッドレスで実行（デフォルトはルールポリシー）、人読ログ、events.jsonl を保存
python -m wargame.cli run --scenario normandy --ticks 40
python -m wargame.cli run --scenario stalingrad --ticks 60 --policy llm --seed 7

# カスタムポートで Web コンソール
python -m wargame.cli serve --host 127.0.0.1 --port 8300
python -m wargame.cli serve --scenario stalingrad
```

フラグ：`--ticks N`、`--policy auto|rule|llm`、`--seed N`、`--scenario <id>`、
`--no-intents`（デフォルト意図を注入しない）。

## 戦役メカニクス

**ノルマンディー 1944**——44×30 マップ（生垣、丘陵、河川と橋、装甲を減速させる沼、鉄道/
道路回廊）。スクリプト天候（6/6 の嵐が史実通り航空戦力を無力化）。移動中の敵を機銃掃射する
航空阻害。増援計画（101 空挺、英第51ハイランド師、12SS、装甲教導師）は指定指揮官に合流。
補給所は奪取され敵に*供給*される可能性。勝利都市をリアルタイム採点。

**スターリングラード 1942**——密集した 20×14 都市グリッド。ヴォルガ川が東翼を分断し、
駅が主要目標。通りは機動回廊、廃墟は掩蔽、市街機動は低速。天候は吹雪→曇り→晴れへ。
双方にスクリプト増援（ソ連親衛歩兵、ドイツ第6軍予備隊）。

## アフターアクションとリプレイ

- **ライブ指標（右パネル）**——陣営別：命令数、応答率と遅延、状況報告、請求、警報、情報、
  決定回数、通信喪失、分離ブロック、LLM フォールバック、残存戦力、目標スコア。
- **レビューカーブ**——戦力・スコア・目標支配の時系列をライブ描画。
- **アフターアクションレポート**——デバッグセンターから Markdown レポート（総覧/指揮系統
  健全性/目標支配時系列/主要イベント）をエクスポート。
- **イベントログとリプレイ**——全イベントが `runs/<run>/events.jsonl` に JSONL で保存。
  `src/wargame/replay.py` がログから推演を再構築（破損行はスキップ）。レポート生成は同一の
  データパイプラインを共有。

## 設定パネル

Web UI でライブ調整：戦闘力、砲兵威力、塹壕ボーナス、地形防御、補給速度と半径、偵察強度、
情報誤差、移動速度、報告間隔、メッセージ遅延と喪失（摩擦）、LLM 温度とティック予算。
エンジン既定値は `DEFAULT_TUNING`（`src/wargame/engine/world.py`）。

## アーキテクチャ

```
src/wargame/
├── schemas.py        プロトコル：メッセージ（8 種）/ 世界アクション / 決定
├── org.py            編制：ポジション = エージェント（ロールカード + 権限 + 設定）
├── bus.py            陣営バス：遅延配達 + 分離チェック + 摩擦
├── camps.py          陣営コンテナ：バス + エージェント + 情報ストア
├── sim.py            スケジューラ：配達→決定→エンジン→偵察、JSONL イベントログ、指標履歴
├── replay.py         JSONL リプレイローダー + Markdown レポート生成
├── agents/
│   ├── base.py       Agent：メールボックス + タスク + 記憶 + SituationView（制限視野）
│   ├── rule_policy.py  ルール脳（オフライン・決定論的・LLM フォールバック）
│   ├── llm_policy.py   LLM 脳（ロールカード + 状況 → ツールコール / JSON 決定）
│   └── tactical.py    最前線戦術エージェント（局所認識 + 自律行動）
├── engine/world.py   決定論エンジン：移動/白兵/砲撃/補給/偵察/天候/航空阻害/
│                     補給所/目標/疲労/士気
├── scenarios/        cross_river / normandy / stalingrad / dynamic（AI インポート）
└── web/              FastAPI（REST + SSE）+ ダークな指揮センター UI（ビルド不要）
```

各ティック：**配達**（摩擦遅延付きのメール）→ **決定**（起床した各エージェントがメッセージと
命令を生成）→ **エンジン**（移動/戦闘/補給/天候…）→ **偵察**（情報が各陣営ストアへ）。
全イベントは SSE でブラウザへ配信され、`runs/*/events.jsonl` に追記されます。

> Python パッケージ名は `wargame`（import パス）、配布名は `wargenerals`、ブランドは
> **将台 WARGENERALS**。リポジトリは歴史的レイアウトを維持。将来のメジャーバージョンで
> ディレクトリ名を統一する可能性があります。

## 開発

```bash
python -m pytest -q             # 47 テスト：指揮系統/分離/決定論/シナリオ/LLM 経路/リプレイ
python -m ruff check src tests  # 警告ゼロ
```

**シナリオ追加**——`src/wargame/scenarios/<name>.py` に統一インターフェース（[シナリオ](#シナリオ)
参照）をエクスポートし、`scenarios/__init__.py` に登録、`tests/` にスモークテストを追加して
全件実行。**ポジション/機構の追加**——エンジンは決定論的でシード付き。エージェントに乱数を
入れないことで戦役の再現性を保ちます。

## FAQ とトラブルシューティング

- **LLM キーがないと動かない？**——いいえ。ルールポリシーがオフラインで全ループを回します。
  `LLM_API_KEY` を設定すると LLM 判断に切り替わります。
- **LLM の判断がおかしい/演習が止まる？**——`WARGAME_LLM_FALLBACK=0` で静かなフォールバック
  をやめ、根本エラーを表示。`LLM_BASE_URL`/`LLM_MODEL` を確認。生のリクエスト/レスポンスは
  エージェントデバッグで確認できます。
- **ポート 8300 が使用中？**——`python -m wargame.cli serve --port <別ポート>`。
- **端末で日本語/中国語が文字化け？**——CLI は UTF-8 を強制。Windows では UTF-8 端末を
  使用（例 `chcp 65001`）。
- **同一シードで結果が違う？**——ポリシーモードを一致させてください。ルールと LLM は元々
  別のポリシーです。
